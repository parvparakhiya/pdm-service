# Serving image. Exact pins, no `>=`.
#
# The previous requirements.txt used `>=` for every package, so two builds a
# week apart shipped different code and a new lightgbm or shap release could
# break production silently. Treat a change here like any other code change.
#
# These are direct dependencies, pinned by hand. Transitive versions are not
# locked; before go-live this should become pip-compile output from an `.in`
# file so the whole tree is reproducible.
#
# NOT PRESENT, and deliberately so:
#   lightgbm, scikit-learn, shap  -> were pulled in only to unpickle a SHAP
#       TreeExplainer at startup. That made the "dependency-light ONNX serving
#       image" ~800 MB larger, tied the artifact to the exact training-time
#       library versions, and made `joblib.load` an arbitrary-code-execution
#       surface on the serving path. Explanations now come from the
#       specification rules, which are exact and need no libraries.
#   pandas -> the domain layer is plain Python floats. Nothing in the request
#       path needs a DataFrame once the rolling-window features are gone.
